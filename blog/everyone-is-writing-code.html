Everyone Is Writing Code, But Who's Still Contributing?

The Strange Paradox of AI in Open Source

November 23, 2026 · 6 min read

Just a few years ago, when a developer had an idea, one of the first things they'd usually do was search GitHub for similar projects.

Maybe they wanted to build an HTTP server, a JSON library, or a simple file management tool.

They'd search around, explore existing projects, read the documentation, and if they found something close to what they needed, they'd try to use it.

If something was missing, they might open an issue, submit a pull request, or even start a discussion with the maintainer.

Of course, it wasn't always like that. Plenty of developers preferred reinventing the wheel even back then! But there was one important barrier: building software from scratch took a lot of time and effort.

That cost often made contributing to an existing project more practical than starting a new one.

But what about today?

Now, you can simply describe your idea to ChatGPT, Claude, or another AI coding tool, and within minutes, you've got the foundation of a new project.

Something that might have taken days or weeks can now turn into a working prototype in just a few hours.

And that's where something interesting starts happening.

We're producing more software than ever, but are we still collaborating as much as we used to?

From Contribution to Independent Creation

Imagine there's an open-source project that already solves 80% of your problem.

In the past, you'd probably consider adding the missing 20%.

Sure, it might take some time to understand the codebase, learn the architecture, and make your changes fit the project's standards.

But in the end, you'd solve your own problem while also improving something that other people could benefit from.

Now imagine the same situation with AI.

Instead of spending hours reading someone else's code, you can simply tell an AI:

"Build me a library that does these things."

And pretty quickly, you'll probably have something that, at least on the surface, gets the job done.

You don't need to understand someone else's architecture, wait for a pull request to be reviewed, or debate technical decisions with a maintainer.

Everything works the way you want it to.

And that's exactly where this convenience might create a bigger problem.

When building from scratch becomes easier than contributing, the motivation to collaborate starts to fade.

100 Developers, 100 Similar Projects

Imagine 100 developers who all need the same kind of tool.

In a more collaborative model, many of them might gather around a handful of existing projects.

One fixes bugs, another improves documentation, someone adds tests, and someone else implements new features.

Eventually, you end up with a few relatively strong projects maintained by a community of developers.

But in today's AI-driven world, each of those 100 developers can build their own version.

The result?

100 GitHub repositories, 100 README files, 100 different architectures, and probably 100 projects doing more or less the same thing.

At first glance, that sounds amazing.

More projects, more code, and more people capable of turning their ideas into reality.

But there's an important question:

Have we actually made 100 times more progress, or have we just solved the same problem 100 different times?

This is where we need to distinguish between production and progress.

More repositories don't necessarily mean a healthier software ecosystem.

Sometimes, one project maintained by 100 developers is far more valuable than 100 projects maintained by one developer each.

Of course, that's not always the case. Independent projects can introduce fresh ideas, different architectures, and even better solutions.

The problem begins when independence becomes the default choice, not because it leads to innovation, but simply because AI makes it so easy.

What AI Still Hasn't Replaced

Open source has never been just about writing code.

A huge part of its value comes from people interacting with each other.

When we contribute to an existing project, we're forced to read someone else's code, understand their technical decisions, and sometimes accept that our own approach isn't necessarily the best one.

We learn how to discuss software design, defend our choices, accept criticism, and work with people who might see things completely differently.

Sometimes, a good code review teaches us more than several days of coding.

AI can generate code, explain it, and even suggest useful improvements.

But collaborating in open source isn't just about solving technical problems.

It's also a social exercise.

It's about listening, giving feedback, accepting feedback, finding common ground, and building something that doesn't belong to just one person.

If we gradually start choosing to work only with AI instead of working with other developers, we might lose part of that culture.

The Maintenance Problem: Building Is Easy, Keeping It Alive Isn't

There's another issue that doesn't get nearly enough attention.

AI has made it much easier to build the first version of a project, but maintaining it is still hard work.

A real project isn't just a few thousand lines of code.

Bugs need fixing, dependencies need updating, security issues need investigating, tests need maintaining, and new changes shouldn't break existing functionality.

Now imagine thousands of similar projects, each maintained by a single developer.

Many of them might be abandoned after a few weeks or months.

Meanwhile, if some of that same energy had gone into improving existing projects, we might have ended up with more stable and reliable software.

AI has lowered the cost of starting a project, but it hasn't necessarily lowered the cost of taking responsibility for it in the long run.

But Do the Numbers Actually Support This?

Here's where we need to be careful.

The fact that more repositories are being created or more code is being generated doesn't automatically mean open-source participation is declining.

In fact, the number of pull requests might also be increasing, simply because AI helps developers write code faster.

But what I think is really worth investigating is the ratio between contribution and independent creation.

Compared to a few years ago, how much developer activity goes into creating new repositories, and how much goes into improving someone else's work?

How many new projects are genuinely innovative, and how many are just slightly different versions of tools that already exist?

And perhaps most importantly, do developers still spend as much time looking for existing solutions before starting something new?

To answer these questions properly, we'd need real GitHub data and a comparison of trends over several years.

So we can't confidently say that collaboration has declined.

But we can raise an interesting hypothesis:

Maybe AI is increasing the speed of software production faster than it's increasing collaboration between developers.

And if that's true, we're looking at a significant shift in programming culture.

Maybe AI Isn't the Problem. Maybe It's How We Choose to Use It.

I'm not saying AI is bad or that we should stop using it.

Quite the opposite.

I think it's one of the most positive developments in the history of software engineering.

AI has made it possible for more people to bring their ideas to life, automate repetitive tasks, and spend more time solving complex problems.

It can even make contributing to open source easier.

For example, we can use AI to explain the architecture of a large project, analyze an issue, write tests for a bug, or help prepare our first pull request.

So the same technology that makes building an independent project easier can also make contributing to existing projects easier.

The real question is how we choose to use that power.

Do we use it to rebuild everything from scratch, every single time?

Or do we use it to improve what others have already built?

Final Thoughts

For years, one of the most important things about open source was that people with different backgrounds, experiences, and skills worked together to solve shared problems.

Someone started a project, and others helped make it better.

Now AI has made it possible for almost anyone to start a project from scratch, often entirely on their own.

That's a huge achievement.

But it might come with a hidden cost.

We could gradually end up in a world where everyone is a creator, but fewer people are willing to spend their time improving someone else's work.

A world full of new repositories, but with smaller communities and less collaboration.

I believe the future of open source doesn't depend only on how good AI becomes at writing code.

It also depends on how willing we are to keep writing code together.

Because maybe the biggest threat AI poses to open source isn't that it will replace developers.

It's that developers might stop needing each other.
